# staging — カメラは、ひとつの手で決める

**①が「何が変わるか」を言った。②がショットを決める。この文書は、②のうちカメラを決める部分である
——そして、カメラが二箇所で同時に決められていたから在る。**

⚠️ **5つ目の段ではないし、欄を1つも足さない。** 走るのは **②の中**
（[`skills/design/SKILL.md`](../design/SKILL-ja.md)）の**第7段**——**`motion` と `duration` の後、
動画の仕様を書く前**である。書くのは **§10**（仕様が初めから持っていた節）と、**§18 の
`Camera Prompt`**（§10 が初めから給っていた欄）である。**置き場に新しいものは何も増えない。**

## ⚠️ なぜ在るか——ひとつの決定が、二度書かれる

カメラは1つの仕様の中で二度書かれる。一度は**設計の決定として**（§10 `CAMERA`）、
一度は**実際に生成器へ届く文字列として**（§18 の `Camera Prompt` スロット）。
形式カードは、初めから、後者は前者から導かれると言っている——

**`Camera Prompt` は §10 から引かれる——カメラ事象を順に、timing・movement・target・speed・
transition**（[`references/formats/video-spec.md`](../../references/formats/video-spec-ja.md) §18。
`specmap.PROMPT_SLOT_SOURCE` も同じ行を持つ）。

⚠️ **§18 は、生成器が受け取る唯一の節である。** だから2つが別の手で書かれると
——§10 をショットを設計する者が、§18 をプロンプトを組み立てる者が——**理由は §10 に残り、
§18 には禁止だけが残る。** 生成器へ渡るのは **「no pan, no push, no rack」** であり、
**その静止が何を守っているかを言う文が1つも無い。** カメラは**置かれなかったもの**として
読まれ、ショットはこの基盤が繰り返し学んでいるものとして読まれる——
**スライドショー、あるいは液体がただ流れているだけ。** 実際に起きた失敗は `HISTORY.md` に在る。

⚠️ **理由の無い禁止は、決定ではなく習慣である。** そして習慣は改訂できない——
次のショットがそれを継ぎ、その次のショットがそれを様式だと思う。

## 決定の順

⚠️ **この順は設計の主張であり、そのうち1本の辺だけが検査される**（第6項、`L33` を通して）。
この順に決め、**決めたそばから書く**——第2項が、他の5つを届くものにする。

**1. カメラがどこに立つか——そして、それが何であるか。** これは §10 の `Camera Language` であり、
**「何をするか」と同じ問いではない。** ⚠️ **「置かれる場所」も「前提が落とされる」も、
どちらも答えである**——そして同じ行に書かれる。主題そのものの縮尺に置かれたマクロの枠、
焦点面が剃刀のように薄い、あるいは**旅をしない紙、つまり「カメラがどこかに居る」という
前提そのものが落ちている。** このショットがどちらなのかを言う。
⚠️ **様式の物理もここに書く**——この様式で運動がいくら掛かるか、どれだけ速くてよいか。
カードの `## Motion character` がそれを書いている場所である（**読み、触らない**）。
そして第6項が、それが生き残る場所である。

**2. 決定はどこに保たれるか——作品自身の文書。** ⚠️ **カメラは `specs/video/<id>.md` の §10 に
保たれるのであり、会話の中ではない。** これは帳簿の話ではない——**§18 は §10 から*導かれる***ので、
会話の中にしか無い決定には、**導く元が無い。** そして導出は大きな音では失敗しない——
**禁止で埋まったスロットが出来上がるだけである。**
**決定を、*その理由とともに*、まず §10 に書く。** §18 はそれを運ぶ写しになり、
**写しであることは検査に見える。**

**3. 予算——このショットが何を費やし、何を費やさないか。** 運動はどの様式でもただではなく、
値段は様式ごとに違う——**ある様式では焦点ラックが1つの身振り全体であり、別の様式では
旅するカメラが絵の蓄えを使い切る。** ここで2つの規則が効く——
- ⚠️ **カメラは様式のものである。形式は狭めてよく、逆さまにしてはならない。** ドリフトを許す
  カードが、*運動は不可能* と書いた仕様になって戻ってきてはならない。
- ⚠️ **辞退は辞退として書く。不可能として書かない。** 形はこれである——
  **「The style permits a focus rack; this shot spends neither.」** 静止するショットは
  **静止を選んだ**ショットである——そう書く。**§18 に**書く。届くのは §18 だからである。

**4. 人物と場面から導く——趣味からではない。** カメラは **`role`**（そのショットの仕事）、
**ショットの中の人物**、**`place` × `time`** の帰結である。
⚠️ **このための語彙は既に在り、誰も其処を指していない。** `rolemap.py` の
`MOTION_PATTERNS` は「枠」の群を持つ——**カメラのみ**（固有基準: **運動が何を開示するか・
速度曲線・被写体との関係**）、**停止**（**停止の張力・その静止が意味するもの**）、
**時間の運動**（**その速度である理由・速度が開示するもの**）。これらは `role` の中で
**`運動（…）`** としてしか引けない（限定つきの綴り、全角括弧）。
⚠️ **②の `motion` は其処を一度も指さない**——だから**カメラこそが主役のショット**が、
空の `motion` と、誰も決めなかったカメラを持つことになる。**カメラ自身が主題のときは、
限定つきの綴りで `role` にそう書き、そのパターンの固有基準でショットを裁く。**
⚠️ **`L15` は限定つきの綴りを註として報告し、違反にはしない**——ゆえに
**パターンを名指すことを強いられはしない。名指すことが、この項目の全部である。**

**5. カメラ事象がいくつか——方針の語彙で。** ショットの単位は**ひとつの変化**であり、
ひとつの変化は**ひとつのカメラ事象**である（[`CLAUDE.md`](../../CLAUDE-ja.md) の固定方針）。
§10 の `Camera Events:` の行が、各事象を**範囲つきで**運ぶ: `0-8s` none、`2-5s` に push。
⚠️ **静止は事象であって、書かないことではない**——「none」は決定であり、他の事象と同じく
範囲つきで書かれる。
⚠️ **カードは事象ごとに4つを求めている——timing・movement・target・speed**——そして
**禁止は、置き方よりずっと書きやすい。**「no pan」は何が起きてはならないかを言い、
**カメラがどこへ行き、何へ向かい、どれだけ速いかを言わない。** ⚠️ **ショットが静止するなら、
その静止が何に費やされるかを書く。動くなら、4つとも書く。** §18 の導出は `transition` を足す。

**6. すべての禁止に理由を——運べる場所に書く。** §18 の `Camera Prompt` に在る禁止は、
§10 に書かれた理由から導けねばならず、**そして理由はそれと一緒に届かねばならない。**
2つの規律があり、どちらも基盤が既に持っている——
- ⚠️ **上書きは上書きとして書く**——**作品自身の記録に**書くのであり、相手側のカードを
  書き換えてではない（[`CLAUDE.md`](../../CLAUDE-ja.md) の固定方針、および
  「壊してはならないもの」: **カードは `distill-essence-engine` の財産である——読み、書き換えない**）。
- ⚠️ **理由は*生成器へ届くスロットの中へ*運ぶ。** §10 に留まった理由は、生成器が一度も
  聞かない理由である——そしてこれが、この文書を生んだ失敗である。

## 何が、どこへ書かれるか

| | どこへ | 何を運ぶか |
|---|---|---|
| **`Camera Language`** | `specs/video/<id>.md` の §10 | カメラがどこに立つか、それが何か、様式の物理 |
| **`Camera Events`** | §10 | 各事象を範囲つきで——timing・movement・target・speed |
| **`Camera Behavior`** | §10 | 理由、そして静止が何に費やされるか |
| **`Camera Prompt`** | §18 | 事象を順に、**理由を一緒に運んで**——生成器へ届く文字列 |
| **`Negative Prompt`** | §18 | 禁じられているもの。⚠️ **カメラの安定の禁止は既知の場合である——§10 に書かれ、生成器へはこのスロットを通って届く**（形式カード自身がそう書いている） |

⚠️ **§10 と §18 は、ひとつの手が書く。** それが機構の全部である——この文書が防ごうとしている
欠落は**受け渡し**の欠落であり、**二人の手の間の受け渡しは、検査で存在させることができない。**

## ⚠️ カメラは様式のものである

- **カードの `## Motion character` を読む**——それが**この様式で運動が何を意味するか**を決める:
  主たる動かし手は何か、静止した枠が許されるか、どれだけの運動が1つの身振り全体か。
  **§10 は*この1本*で何が動くかを決める。** 2つは別の問いであり、2つ目だけに答えた仕様は
  **様式を上書きする。**
- ⚠️ **カードを触らない**（[`CLAUDE.md`](../../CLAUDE-ja.md)）。このショットが様式に逆らわねば
  ならないなら、**除外は作品が書く**——作品自身の言葉で、記録の側に。
- ⚠️ **自分を突き合わせる先のスロットは `Style Motion` である**——7つ目のスロットであり、
  §1–17 からではなくカードから引かれる。§18 の `Camera Prompt` が、`Style Motion` の言う
  様式の振る舞いと矛盾するなら、**仕様がカードを逆さまにしている**（第3項を見よ）。

## 検査が読むもの（`L33`）

**この段を読む層は1つである——`L33`、*§18 の `Camera Prompt` が、様式カードの許した身振りを
禁じていないか。*** 意図して1つだけである——**1つの検査であり、その照合語はカードの側から来る。
この文書の散文からではない。**

- **何を読むか。** `bible.style` → そのカードの `## Motion character`、そして
  [`cards.yaml`](cards.yaml)——この側が16枚を読んだ結果である。**`clause` と `quote` は逐語で
  あり、走るたびにカードへ当てて確かめられる**（引用がもうカードに無ければ
  **「この側の読みが古い」**と報告し、比べない）。
- **いつ鳴るか。** カードが許した身振りが、§18 の `Camera Prompt` の中で**否定の中にしか
  現れない**とき——たとえばカードが焦点ラックを許し、スロットが *no rack* と言うとき。
  **身振りに一度も触れていないショットは鳴らない**——沈黙は禁止ではない。
- **いつ黙るか。** カードがカメラの身振りを**1つも**許していないとき（比べる相手が無い
  ——それは通ったことではなく、**そう報告される**）、カードが読めないとき、動画の仕様が
  1本も見えていないとき、上の辞退の形が在るとき。
- ⚠️ **何を見ていないか。** §10 と §18 が**一致しているか**、理由が良いか、
  その静止が正しい決定だったか。**読むのは、この側が書き留めた身振りだけであり、
  誰も書き留めなかった身振りは鳴らない**——**不完全な読みは、自分から名乗り出ない。**
  そして ⚠️ **`Negative Prompt` スロットは読まない**——そこを、カメラの禁止が実際に
  通っていくことがある。
- ⚠️ **カードの置き場を指して走らせる**——
  `SVL_FORMATS_DIR=references/formats SVL_STYLES_DIR=references/styles`。**これを張らなければ
  このリポジトリ自身のカードが読まれず**、この層も `L20` も註へ落ちる。

## ⚠️ この段が決めないこと

- **カメラが良いかどうか。** 仕様の質を読む検査は無く、**記録の側に発明すべきでもない。**
- **どの経路か、どのモデルか。** §18 の見出しがモデルを名乗り、**その名が経路を決める**
  （`L18`）。⚠️ **経路は、§18 の `Camera` が何を禁じてはならないかを決める**——絵コンテの
  経路では1つのパネルが1つの場面であり、**`no cut` を包括的な規則として書くと、
  パネルが場所を変える唯一の合法な道が閉じる。** 制約は
  [`docs/h3-route.md`](../../docs/h3-route-ja.md) と [`docs/seedance-route.md`](../../docs/seedance-route-ja.md) に在る。
- **作品の禁止。** §18 の `Negative Prompt` は `bible.negative_base` を覆う。
  その一覧は作品のものであり、この段のものではない。

## 言語

- **生成器へ届くものはすべて英語である。** `Camera Prompt`、`Negative`、スロットへ写される
  §10 の一行一行——**英語で書き、訳さない。**
- ⚠️ **例外は語彙自身の綴りである。** `運動（カメラのみ）` と `停止` は **`rolemap.py` の
  文字列**であり、`L15` が読む——**訳せば、検査がそれを引けなくなる。**
  問いは「これは日本語か」ではなく、**「この文字列は届くか」**である。
