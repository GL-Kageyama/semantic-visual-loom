# breakdown — ① 作品をショットへ割る

**1ショットは1つの変化のために在る。** それがこの基盤の固定方針であり、この段はそれを実行する場所である。
**作品を1つの変化の単位で割り**、切れ目ごとに種別を与える。

⚠️ **これはプログラムではなく文書である。** セッションへの指示である。**①分解のコードはこのリポジトリに無い**——
走るコマンドは検査器だけで、それは**この段が書いた記録**に対して走る。

## この段が持つもの

| | 何を | どこに |
|---|---|---|
| **作品台帳** | `style`・`world.rules`・`world.visual_language`・`constants`・`negative_base` | `projects/<name>/bible.yaml` |
| **連続性の語彙** | `characters:` / `locations:` / `props:` と、それぞれの `states:` | `projects/<name>/ledger.yaml` |
| **ショットの列** | `shot`・`unit.before` / `unit.after`・`role`・並び | `projects/<name>/shots/` |
| **開示の変化点** | `disclosure:`——`shot` をキーにした列 | `projects/<name>/ledger.yaml` |

**持たないもの**——`place` / `time` / `mode` / `motion` / `beats` / `duration` と2つの仕様書（**② `design`**）、
および `reference_set` / `forbidden_set` / `attached` / `disclosure_state`（**③ `ledger`**）。

⚠️ **2つの台帳は1本のファイルである。** 連続性と開示は一緒に持つ
（`CLAUDE.md`「The production ledger is one」）。**2つに割らない。**

## 決定の順序

⚠️ **この順序は設計の主張であって、検査器が強制するものではない。** 層は層の順で走り、
`L15`（種別）と `L24`（モード）は**最後に、プロジェクト全体に対して**走る——通り道の関門ではない。
以下は、**次に要るものが要る前に存在するようにする**順序である。

1. **まず作品台帳**——`bible.yaml`。`style` は `distill-essence-engine` に在るカードの名を指し、
   `negative_base` は**作品の禁制**である——下流の画像仕様はすべてこの一覧に対して測られる。
   **間違えると鳴る:** `L17`（`bible.style` が空）・`L21`・`L20`。
2. **連続性の語彙**——`characters:` / `locations:` / `props:` と、それぞれの `states:`。
   ⚠️ **これは帳尻合わせではなく、これ以降のすべてを名指せるようにするものである。**
   `known_keys()`（`check.py`）は参照のキーを**ここからだけ**導出するし、**`L2` のメッセージ自身がそう言う**——
   ショットを割るか、台帳に場所を立てるかである。語彙が無ければ、`place` の引き先も
   `reference_set` の引き先も無い。**間違えると鳴る:** `L8`（台帳に無い参照キー）。
   ⚠️ **`place` が `locations:` のキーであることを見る検査は無い。** それは**データの依存であって、
   鳴る規則ではない**——`L2` が鳴るのは**複数**の場所が欄に並んだときだけである。
3. **1つの変化で割る**——ショットごとに `unit.before` と `unit.after`。
   **間違えると鳴る:** `L1`（前後が同じ＝そのショットは何も起こしていない）・`L0`（ショット0本）。
4. **同一性は仕様の側から取る**——`shot` は §19 の `Instance ID` から末尾の `-<秒>s-<テイク>` を落としたものである。
   ⚠️ **`Segment ID` からは取らない**——同じレンジに2つの綴りが在り、素直に導出すると記録が落ちる
   （`L13` が註で報告する）。**間違えると鳴る:** `L13`。
5. **各ショットに種別を与える**——`rolemap.ROLES` の**15種**から。
   ⚠️ **目録は開いている**——無い名に出会ったら、**その場で定義し、登録する**。
   `総覧` / `語り` / `離脱` はそうやって実測から出た。**間違えると鳴る:** `L15`。
6. **開示の変化点を書く**——`disclosure:`、`shot` をキーにして。
   ⚠️ **変化点だけである——全ショットを並べない。** 変化点の間は直前の状態が続く。
   **間違えると鳴る:** `L7a`・`L7b`・`L9`（遷移がすべて宣言された位置と一致する
   ——**一致は独立性の証拠ではない**）。
7. **回す。**

```bash
python3 engine/ledger/check.py projects/<name>   # 違反と註の両方を読む
python3 engine/ledger/check.py --self-test       # 検査器が鳴ることを確かめる
```

## ⚠️ この段が終わっても赤いままのもの

⚠️ **違反0件は、この段の終了条件ではない。** ①と②は**同じ成果物**を書くので、
検査器は**途中で赤い**——そしてそれは正しい。**この段が失敗したことを教えるのは件数ではなく、
どの層が静かであるかである。**

| 終了時に赤いと期待される層と、その持ち主 | |
|---|---|
| `L11`・`L16`・`L17`・`L18`・`L21`・`L22`・`L23`・`L24` | **② `design` のもの**——まだ何も演出され、仕様化されていない |
| `L5`・`L6`・`L8`・宣言した点より先の `L7a` と `L7b` | **③ `ledger` のもの**——集合はそこで導出される |
| `L25` | **まだ何も生成されていない**——そしてこの段は生成しない |

⚠️ **`--self-test` も回し、それが何のために在るかを読む。** 検査器が鳴ることを確かめるものである
（**169例**）。**何も報告しない検査は、通った検査と同じに見える**——そして両者を見分ける唯一のものが
自己検査である。

## ⚠️ 誰も読まない欄と規則

⚠️ **穴として書く。規則で埋めない。**

- **この段の入力の形が未決定である。** 作品がプロットで来るのか、戯曲で来るのか、小説で来るのかを、
  このリポジトリはどこにも書いていない。**人かセッションと一緒に読み、読んだ形を記録する。**
- **ショットの列にスキーマが無い。** `SCHEMAS` に在るのは `shot-record` であり、それは
  **`duration` を必須にする**——②が決めるものである。**だから①は妥当なショット記録を出せない。**
  列は自分の保っている形で保ち、**②がディスクに乗るまで検査器は何も読まない**ことを知っておく。
- **種別の既定モード（`既定モード`）を、誰も読まない。** `rolemap.py` は定めているが、
  `grep 既定モード engine/ledger/*.py` が返すのは**定義だけ**であり、註すら無い。
  ⚠️ **だから「種別が既定モードを決める」は、読み手のいない原則である。** 規則を発明しないこと。
  そして**`()` は「任意」、`None` は「未定」**である——**2つに同じ顔をさせない。**
- **限定つきの種別の、正典の綴りが未決定である。** `運動（停止）` は引けるし、`L15` はそれを**註**で報告する。
  目録の素の名と限定つきの、どちらが正典かは**決まっていない**——**ここで決めない。**
  ⚠️ 限定をつけられるのは `運動` だけである（`rolemap.QUALIFIABLE`）。
- **台帳を誰が書くかが未決定である。** 連続性の語彙は②が `place` と `time` を書く前に存在しなければならず、
  開示の列は遅く書かれる——だから**1つの段でなければ、この段の内側で割れる。**
  ⚠️ **依存を記録し、割り当ては決めない。**
- ⚠️ **種別はカードとして登録されると宣言され、実体は Python の辞書である。** `CLAUDE.md` は
  種別を「カードとして登録され、育ち、精錬される」と定めている——**目録の実体は `rolemap.py` の `ROLES`** であり、
  書式と様式のカードは `distill-essence-engine` に在って、このリポジトリは**読むが、書き換えない**。
  **種別のカードは、まだ1枚も無い。** 穴として記録する——**読まれている目録の隣に、2つ目の目録を足さない。**

## ⚠️ ここで検査器が決めないこと

- **その変化が正しい変化か。** `unit` は自由文であり、`L1` が問うのは正規化した前後が等しいかだけである。
  **対にしたことと、対を検査できることは別である。**
- **その種別がそのショットに合うか。** `L15` が見るのは値が**引けるか**であって、正しいかではない。
  使われていない種別は**註**で報告される——**それは作品の性質であって、目録の欠陥ではない。**
- **作品の禁制が何であるべきか。** `negative_base` は作品についての判断である。

## 言語

- **`role` の値は日本語である。** 生成器へ渡る文字列ではない（§1–20 に欄が無く、モデルが見る文に一度も現れない）
  ——だから目録の `dialogue` や `establishing` は**読みのための註であって、綴りの半分ではない。**
- **生成器へ渡る文字列は英語である。** 仕様・プロンプト・Negative は英語で書き、**訳してはならない**——
  訳すと出力が変わる。効いてくるのは②だが、**ここに書くのは、`role` が例外である理由がそれだからである。**
- **文書の正典は英語であり**、ミラーは同じディレクトリに並ぶ——[`CLAUDE.md`](../../CLAUDE-ja.md) を見ること。
