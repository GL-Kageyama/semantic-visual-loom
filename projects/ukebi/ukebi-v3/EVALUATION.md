# 設計の評価 — 三つの台帳（混ぜない）

**設計を評価してから、改稿する。** 対象は `PLAN.md` と `episodes/epNN.md`。
ショット記録でも §1–20 でもない——**まだ存在しないもの**を評価しない。

⚠️ **この文書は評価の設計であって、評価そのものではない。** 走らせるのは人（か、次のセッション）。

## 0. なぜ別の門が要るか

| 既にある門 | 何を見るか | この設計に使えるか |
|---|---|---|
| `check.py` | `bible` / `ledger` / `shots` / `specs` の破綻 | **まだ走らない。** ショットが0本だから |
| 文学評議会（13次元） | 散文10話の物語としての強さ | **使わない。** loop02 で平均71.92、目標60を通過済み。設計を当てれば物語を二度裁く |
| guide-loom `guide-viewer` | 初見の読者が**説明**を復元できるか | **そのままは使わない。** この作品は説明を意図的に落とす。理解度を上げる改稿は設計の逆行 |
| guide-loom の二台帳の規律 | 別の物差しを混ぜない・読者に設計を見せない・門は合否 | **これだけ写す。** 平均にしない。台帳を分ける |

**設計の読み手は、観客ではない。** 次の段でショットを切るセッションだ。
だから問うのは「伝わるか」ではなく、**「この設計だけで切れるか」「原作を保っているか」「撮れるか」**。

## 1. 三つの台帳

### A. 実行者テスト（3人・互いに見ない）

**目的**: 設計が次の段に対して自己完結しているか。

**渡すもの**
- `PLAN.md`
- `episodes/ep03.md` から「未決」を除いた写し
- 原作の `草稿/ショット表_第3話.md`
- `台帳/` の該当（踏切・台帳・記憶・フミ・送り火）——**花は渡さない**（第3話は不在）
- 画像31枚の一覧（**画像そのものは渡さない**。参照の可否だけ）

**渡さないもの**
- `構想/design.md`（原作の設計。ただし台帳と行は渡す）
- 文学評議会の結果（`評価/`）
- 著者のメモ・この文書・前の評価

**させること**
1. 第3話のショット割りを書く。1行1ショットで——
   `unit.before` / `unit.after` / `place` / `time` / `population` / `body_parts` / `reference_set`（鍵） / `duration`。
   §1–20 は書かない。**切るだけ。**
2. **推測した箇所**を全部挙げる。「設計に無いので、こう決めた」の一覧。
3. 曖昧だった箇所を、文書の座標（`ep03.md` のどの行）で挙げる。

**返す形**: JSON。`shot_list` / `guessed` / `ambiguous` / `shot_count`。

**門**
- **重大な曖昧さが無い。** 重大＝切れ目・参照・人数が変わる推測。
- 3人の `shot_count` は揃わなくてよい。**揃わない理由が設計に書かれていれば通す。**
  書かれていない差は、そのまま欠陥。
- 3人が同じ推測をしたら、**その推測は設計の穴**（多数決で正しくしない）。

**させないこと**
- 物語の良し悪しを言う。
- §1–20 を書く。
- 行に無いショットを発明する（割るのはよい）。

### B. 原作の番人（1人）

**目的**: 設計が `design.md` と `台帳/` を保っているか。

**渡すもの**: `PLAN.md`・`episodes/epNN.md`・`構想/design.md`・`構想/改稿裁定.md`・`台帳/`・`草稿/`・ショット表。

**見ること**

- 八器官・開示の順序・定型句9回・花の台詞4つ・記憶の規則を変えていないか。
- **発明した状態**が無いか（台帳に無い火の段・印・衣装・小道具）。
- **原作の側の食い違い**を、設計が握りつぶしていないか。
  既知: 第7話の判の押し手（台帳は「送り火が押す」、草稿と表は「花が押す」）。

⚠️ **この一覧は既知の例である。一覧に無い食い違いを探す。** 既知は第7話の1件だけだ。

**返す形**: JSON。`contradictions`（両側の座標つき）/ `inventions` / `dropped` / `unrecorded_departures`。

**門**
- **記録されていない食い違いが無い。** 食い違い自体は退役ではない——**記録と裁定があれば通す。**
- 発明は、理由が設計に書いてあれば通す。

### C. 撮影可能性（1人）

**目的**: WAN 3.0 と31枚で、この設計が撮れるか。

**渡すもの**: `PLAN.md`・`episodes/epNN.md`・sVL の固定方針（`CLAUDE.md`）・

**門**

## 2. ループ

1. **パイロット（第3話）だけ**に A・B・C を当てる。他の9話は、その話を切るときに当てる。
2. 返ってきた知見を、**設計文書だけ**へ反映する。原作・画像・台帳は、著者の裁定が無い限り動かさない。
3. **新しい評価者**で再実行する。前の返答は渡さない（写しを読ませない）。
4. 止める条件——**点ではなく、三つの門**。
   - A: 重大な曖昧さが無い。
   - B: 記録されていない食い違いが無い。
   - C: 閉じていない blocker が無い。
5. **反対は残す。** 著者が採らなかった指摘は、理由とともに `episodes/epNN.md` の「未決」へ残す。消さない。

**平均を出さない。** 三つの台帳は混ぜない。guide-loom の 75 も、基準−10 も、この作品には使わない。

## 3. やらないこと

- 評価者に設計を書き換えさせる。**返すのは座標つきの指摘だけ。**
- 文学評議会を設計に当てる。**物語は loop02 で通過済み。**
- `guide-viewer` の理解度を、この作品に当てる。**説明を落とす設計を、説明の門で裁かない。**
- 評価者を増やして平均を上げる。**3人で足りないなら、設計が悪い。**
- 指摘を全部採る。**採らない指摘は、理由を書いて残す。**
