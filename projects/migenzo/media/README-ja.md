# `media/` — 著者が落とす生成物の置き場

**ここは基盤が読まない。** 生成物（画像・動画）を置く場所であり、
`check.py` も `semantic.py` もこのディレクトリを開かない。

## ⚠️ 標本は 2026-09-25 にここへ移った

2026-09-25 まで、焼かれた画像は `specs/image/` に、焼かれた動画は `specs/video/` に、
それぞれ自分の仕様の隣に座っていた。
**`take.file` は `media/` の中のファイル名を名乗る**（`schemas/take.schema.json`）——
だから標本を、記録が指す1箇所へ移した。
⚠️ **仕様は移っていない。** `specs/` は仕様の場所であり、こことは別の場所である。
⚠️ **両者は、置かれている場所ではなく、何であるかで見分ける。**

## ⚠️ 画像も動画も、**ここ**に置く

⚠️ **`takes/` に動画を置かない。** `takes/` は**記録**（`*.yaml`）の場所である——
**物と記録を同じ場所に混ぜない。** 実物はここへ、記録は `takes/` へ。

⚠️ **繋いだ物をここに置かない。** ここは**標本**の場所であり、**作品**の場所ではない——
繋いだものは `../renders/` である。
⚠️ **混ぜると、消えた標本と在る作品の区別が付かなくなる。**

## ⚠️ ここに**無い**ものが2つ在る

`specs/image/生成時参照イラスト/`（2枚）——**生成の入力である。**
⚠️ **この作品のショットの標本ではない**——他所（`distill-essence-engine`）で作られ、

## ⚠️ 名前

⚠️ **頭の `NN_MM_` はショットとセグメントである**——`06_01_…` は、§19 が `Segment ID: 06-1` と
言う1本のファイルである（**名前を §19 に突き合わせて読んだ**）。
そのあとに、生成器が返してきた名前がそのまま続く。
⚠️ **この綴りは動く。** いま在る名前を数えてこの文書に書かない——**書けば食い違う。**

## ⚠️ Git LFS

⚠️ **`.mp4` と `.png` は Git LFS が追う**（`.gitattributes`）。

```gitattributes
*.mp4 filter=lfs diff=lfs merge=lfs -text
*.png filter=lfs diff=lfs merge=lfs -text
```

⚠️ **置いただけでは LFS にならない。** `git add` して初めて**ポインタ**になり、
実体は `.git/lfs/objects/` へ入る。
**追跡されないままのファイルは、リポジトリの中に存在しない**——
**clone した人には見えず、消えても誰も気づかない。**
⚠️ **実体は push のときに一緒に上がる。**

⚠️ **`git lfs ls-files` の2列目は、ローカルの実体の有無ではない。**
`*` は「完全なオブジェクト」、`-` は「**LFS ポインタ**」——つまり
**ディスク上のコピーがポインタ（または不在）である**印であり、
**実体が `.git/lfs/objects/` に在るかは言っていない。**
⚠️ **実体を確かめたいなら `.git/lfs/objects/<oid の先頭1〜2字>/<3〜4字>/<oid>` を開く。**
