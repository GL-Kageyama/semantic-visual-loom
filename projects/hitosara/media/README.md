# `media/` — 著者が落とす生成物の置き場

**ここは基盤が読まない。** 生成物（画像・動画）を置く場所であり、
`check.py` も `semantic.py` もこのディレクトリを開かない。

## ⚠️ 画像も動画も、**ここ**に置く

⚠️ **`takes/` に動画を置かない。** `takes/` は**記録**（`*.yaml`）の場所である——
**物と記録を同じ場所に混ぜない。** 実物は `media/`、記録は `takes/`。

⚠️ **編集したもの（繋いだもの）をここに置かない。** ここは**標本**の場所であって、
**作品**の場所ではない——繋いだものは `../renders/` である。
⚠️ **混ぜると、標本の欠落と作品の存在が見分けられなくなる**——
**「記録の無いテイク」の顔をした作品**が、ここに並ぶことになる。

⚠️ **`.mp4` と `.png` は Git LFS で追跡する**（`.gitattributes`）。

```gitattributes
*.mp4 filter=lfs diff=lfs merge=lfs -text
*.png filter=lfs diff=lfs merge=lfs -text
```

⚠️ **置いただけでは、LFS にならない。** `git add` して初めて
**133バイトのポインタ**になり、実体が `.git/lfs/objects/` に入る。
**untracked のままのファイルは、リポジトリの中に存在しない**——
**clone した人には見えないし、消えても誰も気づかない。**

⚠️ **実体は push のときに一緒に上がる。** ポインタだけ上がっても、
**clone した人は動画を持てない。**

⚠️ **`git lfs ls-files` の2列目は、手元の実体の有無ではない。**
`*` は「完全なオブジェクト」、`-` は「**LFS ポインタ**」を指す（`git lfs ls-files --help`）——
つまり**ディスク上の写しがポインタ（または不在）**であることの印であって、
**`.git/lfs/objects/` に実体が在るかは言わない。**
⚠️ **実際に、`-` なのに実体が在るファイルが3本ある**（`2__` `5__` `6__` の旧名——
**オブジェクトは手元に在り、ディスク上の写しだけが無い**）。
**実体を確かめるなら `.git/lfs/objects/<oid の1〜2字>/<3〜4字>/<oid>` を開くこと。**

⚠️ **ポインタが解決できない状態が、実際に生まれた**（と、いちど記録した）。
`02__20260913-….mp4` は **133バイトのポインタ**としてコミットされ、
**そのファイルは作業ツリーから消えた。**
⚠️ **だが、その実体は手元の LFS に在る**——`0c119d5c…`（10,456,290 バイト）。
ffprobe は `1920x1080 / 60 フレーム / 2.000s` と読む。
⚠️ **「実体がどこにも無い」と書いたのは誤りだった**（`HISTORY.md` の 0.17.1）。
⚠️ **リモートに在るかは、ここからは測れない。**

⚠️ **ファイル名は `NN__` で始める**（`01__` … `10__`）。名前は記録を引く手がかりである。
⚠️ **その読み方——先頭の数字がショット番号である——は、著者が1本をショット番号で
指したことで確かめられた**（`6__78bbaadd-….mp4` = ショット6、2026-09-13）。
**推測ではなく、1点の実測に支えられた読みである。**
⚠️ **この綴りは動く。** いま在る名前を、この文に数えて書かない——**書けば食い違う。**

⚠️ **生成物は大きなバイナリである。** 置くかどうかは著者が決める。
**このリポジトリは、生成を実行しない**（API キーが環境に無い）。
著者が手で回し、戻ってきたものを `takes/` に**記録**する——
**置いたことは、記録したことではない。**

⚠️ **このディレクトリに物が在ることは、何の報告でもない。**
`takes/` の空は報告される。**こちらの空も、こちらの充実も、報告されない。**
**ファイルが在ることは、そのショットが通ったことではない。**

## ⚠️ `L25` は、この宣言を守っている

`L25` は `take.file` が名乗るファイルを**開かないし、`stat` もしない**——
だから**このディレクトリの中身と、`takes/` の記録が食い違っていても、機械は鳴らない。**

⚠️ **その食い違いには2つの向きがある。** **① ここに在るのに、記録が無い。**
**② 記録が名乗っているのに、ここに無い。**——**②は実際に起きた。**
`02__20260913-….mp4` を名乗るテイクが `takes/` に在るが、**そのファイルはもう無い。**
`6__78bbaadd-….mp4` も同じである——**名乗るテイクが在り、ファイルは無い。**
⚠️ **どちらも、実体は手元の LFS に在る**——**消えたのは名前であって、物ではない。**
⚠️ **だからテイクの本数と、ここの mp4 の本数は一致しない。** **どちらの向きも、機械は鳴らさない。**
⚠️ **本数をこの文に書かない。** 本数は動く——**書けば食い違う。**

⚠️ **この穴を検査で塞ぐなら、この宣言（「基盤はここを開かない」）を先に変えることになる。**
**塞ぐかどうかは未決定である**——`media/` を読ませれば、記録と実物の食い違いは機械で鳴る。
だがそのとき、**基盤はバイナリの置き場を覗く者になる。**

⚠️ **`*.md` は読まれない。** だからこの文は素材として数えられない。
