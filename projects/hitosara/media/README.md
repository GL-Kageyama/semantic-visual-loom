# `media/` — 著者が落とす生成物の置き場

**ここは基盤が読まない。** 生成物（画像・動画）を置く場所であり、
`check.py` も `semantic.py` もこのディレクトリを開かない。

## ⚠️ 画像も動画も、**ここ**に置く

⚠️ **`takes/` に動画を置かない。** `takes/` は**記録**（`*.yaml`）の場所である——
**物と記録を同じ場所に混ぜない。** 実物は `media/`、記録は `takes/`。

⚠️ **`.mp4` と `.png` は Git LFS で追跡する**（`.gitattributes`）。

```gitattributes
*.mp4 filter=lfs diff=lfs merge=lfs -text
*.png filter=lfs diff=lfs merge=lfs -text
```

⚠️ **置いただけでは、LFS にならない。** `git add` して初めて
**133バイトのポインタ**になり、実体が `.git/lfs/objects/` に入る。
**untracked のままのファイルは、リポジトリの中に存在しない**——
**clone した人には見えないし、消えても誰も気づかない。**

⚠️ **実体は push のときに一緒に上がる。** ポインタだけ上がっても、
**clone した人は動画を持てない。**

⚠️ **ポインタだけ在って実体が無いファイルが、実際に生まれた。**
`02__20260913-….mp4` は **133バイトのポインタ**としてコミットされ、
**実体は手元の LFS にも、リモートにも無かった。**——**消すことになった。**
**`git lfs ls-files` の2列目が `*` なら実体が手元に在り、`-` なら無い。**
⚠️ **`-` を見たら、それは「在る」ではない。**

⚠️ **ファイル名は `NN_` で始める**（`01_` … `10_`）。⚠️ **いま `2__…` という名前の
動画が1本ある**——**`NN_` の形から外れている。** 名前は記録を引く手がかりである。

⚠️ **生成物は大きなバイナリである。** 置くかどうかは著者が決める。
**このリポジトリは、生成を実行しない**（API キーが環境に無い）。
著者が手で回し、戻ってきたものを `takes/` に**記録**する——
**置いたことは、記録したことではない。**

⚠️ **このディレクトリに物が在ることは、何の報告でもない。**
`takes/` の空は報告される。**こちらの空も、こちらの充実も、報告されない。**
**ファイルが在ることは、そのショットが通ったことではない。**

## ⚠️ `L25` は、この宣言を守っている

`L25` は `take.file` が名乗るファイルを**開かないし、`stat` もしない**——
だから**このディレクトリの中身と、`takes/` の記録が食い違っていても、機械は鳴らない。**
**実測: mp4 は3本ここに在るが、`video` のテイクは2本しか記録されていない。**
⚠️ **差の1本は、記録の側の穴である。** そして**その穴は `L25` の註が文章で報告する**——
**数を数える検査ではなく、読む者への報告として。**

⚠️ **この穴を検査で塞ぐなら、この宣言（「基盤はここを開かない」）を先に変えることになる。**
**塞ぐかどうかは未決定である**——`media/` を読ませれば、記録と実物の食い違いは機械で鳴る。
だがそのとき、**基盤はバイナリの置き場を覗く者になる。**

⚠️ **`*.md` は読まれない。** だからこの文は素材として数えられない。
