# `takes/` — 戻ってきたものの記録

テイクの記録は `*.yaml` である（`schemas/take.schema.json`）。**1つの標本につき1枚。**

⚠️ **`media/` と `takes/` は別である。** `media/` は**物**の置き場、`takes/` は**記録**である。
**置いたことは、記録したことではない**——だから両方を見ないと、いま何が在るかは分からない。

## 記録の読み方

| 欄 | |
|---|---|
| `shot` / `kind` / `index` | どのショットの、どちらの経路の、何本目か。⚠️ **`index` は `(shot, kind)` ごとに数える**——画像と動画は別の列である |
| `file` | `media/` の中のファイル名。⚠️ **名乗りであって、存在の証明ではない**（下記） |
| `provider.model` | 生成モデル。`specmap.MODELS` の目録を引く |
| `params.source` / `source_version` | 投入した文字列の**正典の場所**と、**その時の版**。⚠️ **写しは置かない**——写しは食い違う |
| `verdict.machine.measured` | **戻ってきたファイルから実測した値。**「頼んだ値」と「来た値」は別である |
| `adopted` | 採用したか。**採用は選別であり、作者は編集である** |

⚠️ **`file` が指す物が在るかは、検査は確かめない。** 基盤は `media/` を開かないと
`media/README.md` が宣言しており、`L25` はその宣言を守っている。
**`take.file` は名乗りであり、証明ではない**——この穴は `L25` が註で報告する。

## いま在るもの

**13本**（`image` 11 ／ `video` 2）。採用と書いてあるのは **9本**である。

- ⚠️ **`media/` の mp4 の本数と、`video` のテイクの本数は一致していない。**
  **置いてあって記録が無いものがある**——**その差は `L25` の註がその場で数えて言う。**
  ⚠️ **この文に本数を書かない。** 本数は動く——**書けば食い違う。**
- **`05` の動画・`03` の画像**のように、**経路の片方だけが進んでいる**ショットがある。
  経路は2つ在るので、**片方だけ進んでいる状態は「未完成」ではなく「そういう状態」である**——
  だが**どちらが進んでいるかを記録から読めなければ、それは状態ではない。**

## ⚠️ 空を OK と言わない

`check.py` は `takes/` が空なら、こう報告する——

> `takes/` は在るが、**テイクの記録が1本も無い**——生成は一度も走っていない。
> 「テイク0件」は「違反0件」ではない。**選別の検査が空である。**

**0件は合格ではない。** 記録が在っても同じである——`L25` は
**「確かめていないこと」を註で並べる**（突き合わせる相手が無い画像の10本、
仕様が生成のあとに直っている件、`file` の存在）。**註を読むこと。**

⚠️ **`*.md` は読まれない。** `Project.__init__` は `*.y*ml` だけを読む。
だからこの文はテイクとして数えられない——**数えられては困る。**
