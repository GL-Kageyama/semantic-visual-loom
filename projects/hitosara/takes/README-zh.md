# `takes/` — 回来的东西的记录

镜次的记录是 `*.yaml`（`schemas/take.schema.json`）。**每一个标本一张。**

⚠️ **`media/` 与 `takes/` 是两回事。** `media/` 是**物**的放置处，`takes/` 是**记录**。
**放下过，不等于记录过**——所以不把两边都看一遍，就不知道现在有什么。

## 记录的读法

| 栏 | |
|---|---|
| `shot` / `kind` / `index` | 哪个镜头的、哪条路径的、第几本。⚠️ **`index` 按 `(shot, kind)` 分别计数**——图像与视频是不同的序列 |
| `file` | `media/` 里的文件名。⚠️ **是声称，不是存在的证明**（下文） |
| `provider.model` | 生成模型。拉取 `specmap.MODELS` 的目录 |
| `params.source` / `source_version` | 投入的字符串的**正典位置**，以及**当时的版本**。⚠️ **不要保留副本**——副本会相互矛盾 |
| `verdict.machine.measured` | **从回来的文件里实测的值。**「要求的值」与「来的值」是两回事 |
| `adopted` | 是否采用。**采用是选别，作者是编辑** |

⚠️ **`file` 指的东西在不在，检查不会确认。** 基盘不打开 `media/`，
`media/README.md` 这样宣言着，而 `L25` 守着那个宣言。
**`take.file` 是声称，不是证明**——这个洞由 `L25` 在注里报告。

## 现在存在的东西

**镜次有多少，就有多少张 `*.yaml`。** ⚠️ **不要把数量写在这里**——数量会动，
**写下来就会矛盾。** 数量与明细，**`L25` 的注会当场数出来说。**

- ⚠️ **镜次的数量与 `media/` 里 mp4 的数量不一致。** 方向有两个——
  **① `media/` 里存在，却没有记录**（放下过，不等于记录过）。
  **② 记录声称的文件，已经不在了**（`file` 是声称，不是证明）。
  ⚠️ **两个方向，机器都不会报警**——因为 `L25` 不打开 `media/`。
- 路径有两条，所以**可能存在只前进了一侧的镜头。**
  **只前进了一侧的状态不是「未完成」，而是「就是这样一种状态」**——
  但**如果从记录里读不出是哪一侧在前进，那它就不是状态。**
  ⚠️ **哪几个镜头是这样，不要写进这段文字**——**会动。** 数记录就知道了。
- ⚠️ **`file` 里的名字，会在作者手里动。** 即使改名机器也不会报警（因为不打开 `media/`）
  ——**记录会悄悄地变旧。** 所以**在读记录之前，先数 `media/`。**

## ⚠️ 不要把空叫作 OK

`check.py` 在 `takes/` 为空时，会这样报告——

> `takes/` 存在，但**镜次的记录一本都没有**——生成一次也没有跑过。
> 「镜次0件」不是「违规0件」。**选别的检查是空的。**

**0件不是合格。** 有记录也一样——`L25` 会
**在注里列出「没有确认的事」**（没有可对照对象的图像的镜次、
规格在生成之后被改过的情况、`file` 的存在）。**读注。**

⚠️ **`*.md` 不会被读。** `Project.__init__` 只读 `*.y*ml`。
所以这段文字不会被算作镜次——**被算进去就麻烦了。**
