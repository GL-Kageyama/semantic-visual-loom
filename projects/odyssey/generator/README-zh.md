# `generator/` — 撰写 31 份规格正文的地方

**本目录就是 `specs/video/` 正文的原稿。** 34 份规格中有 **31 份是产物**，它们在这里撰写、修改。
其余 3 份——`s01`、`s03`、`s05`——是**手写**的；对这 3 份而言，`specs/video/` 中的文件本身就是原稿。
`gen.py` 从不触碰它们。

⚠️ **为什么它在这里。** 直到 2026-09-29，它一直待在 `/tmp`。`/tmp` 是会消失的。
**失去生成器的规格仍然可读，却再也无法修改**——这比没有生成器更糟，
**因为文件里没有任何一处说明这一点。**

## 运行方式

```bash
cd projects/odyssey/generator
python3 gen.py                  # 现有的全部 content 模块
python3 gen.py s12 s16          # 只跑指定的镜头
python3 verify.py               # 在全部 34 份规格上检查不变量
```

`gen.py` 写入 `../specs/video/odyssey-sNN.md`，**并在写入之前断言**——
槽位缺失、与镜头记录不符的节拍表，或 §18 槽位内出现 CJK，都会让它中止。

## 谁持有什么

| 文件 | 持有什么 |
|---|---|
| `lit.py` | 检查所读取的冻结不变量——作品的四个常量、§18 的 `Negative`（一行，34 份共通）、`Style Motion`、§18 前言的开头，以及同一性区块。⚠️ **由 `freeze.py` 生成。请勿手工编辑。** |
| `freeze.py` | **靠读取**重新抽取这些字符串（绝不重打）——从三份手写规格、台账与形式卡片中 |
| `shared.py` | 出于同样的理由，从 `s01`/`s03`/`s05` 抽取的不变片段 |
| `common.py` | 共通的散文：世界的概念、世界的规则、禁止的底线、共通的 `must_not` |
| `tpl.py` | **§1–20 的全部**——章节顺序、§18 的七个槽位、模板自身的句子，以及维持它们的断言 |
| `content/sNN.py` | **单个镜头自身的散文——真正被撰写的东西。**共 31 个文件 |
| `roster.json` | 从 `shots/*.yaml` 取得的逐镜头事实；由 `roster.py` 重建 |
| `gen.py` | 把一个 content 模块渲染成一份规格 |

**区分持有者是关键所在。** 模板持有**必须跨镜头完全一致**的东西；
content 模块只持有**那个镜头自身**的东西。
把模板持有的字符串写进 content 模块，它就会重复出现两次。

## 检查工具

它们只读。每一个都只给出候选，**没有一个做判断**。
只有 `verify.py` 必须在每一批之后干净地返回。

| 文件 | 它问的问题 |
|---|---|
| `verify.py` | 34 份是否都带有同样的不变量、七个槽位、仅含英语的槽位，以及同一性区块与「画面中没有人」的主张之间没有矛盾？ |
| `orphan.py` | 有没有不带区块的镜头，却带着指向区块的句子？ |
| `absence_probe.py` | 哪些规格把同一性区块与「没有人」的主张放在了同一个槽位？ |
| `universals.py` | 哪些句子声称了比该镜头更广的范围——`every shot`、`all thirty-four`？ |
| `contradiction.py`、`peek.py`、`ten.py` | 出自同一次检视的更窄的探查 |

⚠️ **`universals.py` 以类别为键，而不是以措辞为键。** 以你预期的措辞为键的扫描
**会漏掉变体**——同一次工作中这发生了三次：一个镜头动词不同，另一个根本不含被搜索的措辞，
还有两个以不同的句式引入了同一个虚假的全称。

## ⚠️ 四个容易弄错的地方

1. **对这 31 个镜头而言，手工编辑 `specs/video/*.md` 就是在编辑产物。**
   下一次 `gen.py` 会覆盖它。请改 `content/sNN.py` 再重新生成。
   对 `s01`/`s03`/`s05` 则相反——规格文件就是原稿。
2. **`s05` 是手写的，却带有同一性区块。**「三份手写规格没有区块」是错的，而它曾被相信过一次。
3. **`ROOT` 取自 `__file__`，写作 `parents[3]`。** 它曾被写成 `parents[2]`，
   指向 `<repo>/projects`——于是 `gen.py` 把 **31 份写进了 `<repo>/projects/projects/`，
   而验证照样通过**，因为真正的规格一个字节都没有被碰过。
   打印出来的路径看起来也没错（它是用 `relative_to(ROOT)` 打印的）。
   **目标存在，并不是它是正确目标的证据。**
   `gen.py` 与四个读取器现在在做任何事之前先断言根目录。
4. **`roster.json` 是导出物，而过期的副本是沉默的。** 当 content 模块没有声明节拍表时，
   `gen.py` 会从这里读取。改动镜头记录之后，请用 `roster.py` 重建——
   过期副本不会在规格中产生任何差异，**因而不会被察觉。**
