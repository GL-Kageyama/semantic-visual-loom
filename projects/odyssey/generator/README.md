# `generator/` — where the prose of 31 specifications is written

**This directory is the source of the prose in `specs/video/`.** Thirty-one of the thirty-four
specification files are **build products**; this is where they are written and revised.
The other three — `s01`, `s03`, `s05` — are **hand-written**, and for those the file in
`specs/video/` is itself the source. `gen.py` never touches them.

⚠️ **Why it lives here.** Until 2026-09-29 it lived in `/tmp`. `/tmp` is volatile, and a
specification whose generator is gone **can still be read but can no longer be revised** —
which is a worse state than having no generator at all, because nothing about the file says so.

## Run it

```bash
cd projects/odyssey/generator
python3 gen.py                  # every content module present
python3 gen.py s12 s16          # named shots only
python3 verify.py               # the invariants, across all 34 specifications
```

`gen.py` writes `../specs/video/odyssey-sNN.md`, and **asserts before it writes** — a missing
slot, a beat table that disagrees with the shot record, or CJK inside a §18 slot stops the run.

## What owns what

| file | what it owns |
|---|---|
| `lit.py` | the frozen invariants the checks read: the four work constants, the §18 `Negative` (one line, all 34), `Style Motion`, the §18 preamble head, and the identity block. ⚠️ **GENERATED by `freeze.py` — do not edit by hand.** |
| `freeze.py` | re-extracts those strings **by reading**, never by retyping, from the three hand-written specs, the ledger and the format cards |
| `shared.py` | the invariant chunks, extracted from `s01`/`s03`/`s05` for the same reason |
| `common.py` | the shared prose: the world concept, the world rules, the negative floor, the common `must_not` |
| `tpl.py` | **all of §1–20**: the section order, the seven §18 slots, the template's own sentences, and the assertions that hold them |
| `content/sNN.py` | **one shot's own prose — the thing that is actually authored.** 31 files |
| `roster.json` | every per-shot fact taken from `shots/*.yaml`; `roster.py` rebuilds it |
| `gen.py` | renders one content module into one specification |

**The split of ownership is the point.** The template owns everything that must be identical
across shots; a content module owns only what is that shot's own. Writing a template-owned
string into a content module produces it twice.

## The audit tools

They only read. Each prints candidates; **none of them decides**. `verify.py` is the one that
must come back clean after every batch.

| file | question it asks |
|---|---|
| `verify.py` | do all 34 specifications carry the same invariants, the seven slots, English-only slots, and no contradiction between the identity block and a claim that nobody is in frame? |
| `orphan.py` | does a specification point at the identity block in a shot that does not have one? |
| `absence_probe.py` | which specifications put the identity block **and** a person-absence claim in the same slot? |
| `universals.py` | which sentences claim a scope wider than the shot — `every shot`, `all thirty-four`? |
| `contradiction.py`, `peek.py`, `ten.py` | narrower probes from the same review |

⚠️ **`universals.py` keys on the class, not the phrase.** A scan keyed on the phrase you
expect **misses the variant**, and this happened three times in one session: one shot used a
different verb, another was sought by a phrase it did not contain, and two more introduced the
same false universal in a different construction.

## History

- `_oneoff/` — the four edit scripts from 2026-09-29. ⛔ **Do not re-run them.** They are a
  record of what was changed, not a tool: what they patched no longer exists.
- `CONTRACT.md` — the contract the 31 specifications were commissioned under, with what a
  writer must read, what the template owns, and how to check the result.

## ⚠️ Four things that are easy to get wrong

1. **For 31 shots, editing `specs/video/*.md` by hand is editing a build product.** The next
   `gen.py` overwrites it. Edit `content/sNN.py` and regenerate.
   For `s01`/`s03`/`s05` the reverse holds — the specification file is the source.
2. **`s05` is hand-written *and* carries the identity block.** "The three hand-written specs
   have no block" is false, and it was believed once.
3. **`ROOT` is derived from `__file__`, as `parents[3]`.** It was once written `parents[2]`,
   which pointed at `<repo>/projects` — and `gen.py` then wrote 31 specifications into
   `<repo>/projects/projects/` **while the verification passed**, because the real
   specifications were never touched. The printed path looked correct too: it was printed
   `relative_to(ROOT)`. **A destination existing is not evidence that it is the right one.**
   `gen.py` and the four readers now assert the root before doing anything.
4. **`roster.json` is derived, and a stale copy is silent.** `gen.py` reads the beat table from
   it when a content module declares none. Rebuild it with `roster.py` after the shot records
   change; a stale copy produced no diff in the specifications and would not have been noticed.
