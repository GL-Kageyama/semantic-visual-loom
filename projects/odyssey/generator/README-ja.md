# `generator/` — 31本の仕様の本文を書く場所

**このディレクトリが、`specs/video/` の本文の原本である。** 仕様34本のうち**31本は生成物**であり、
ここで書かれ、直される。残る3本——`s01`・`s03`・`s05`——は**手書き**で、これらについては
`specs/video/` のファイルが原本である。`gen.py` はこの3本に触らない。

⚠️ **なぜここに在るか。** 2026-09-29 まで `/tmp` にあった。`/tmp` は揮発する。
**生成器を失った仕様は、読めるが二度と直せない**——これは生成器が無いより悪い。
**ファイルのどこにも、そうとは書いてないからである。**

## 走らせ方

```bash
cd projects/odyssey/generator
python3 gen.py                  # 在る content モジュール全部
python3 gen.py s12 s16          # 名指ししたショットだけ
python3 verify.py               # 不変量を、仕様34本すべてで
```

`gen.py` は `../specs/video/odyssey-sNN.md` を書き、**書く前に assert する**——
スロットの欠落、ショット記録と食い違うビート表、§18 のスロット内の CJK で止まる。

## 何が何を持つか

| ファイル | 持っているもの |
|---|---|
| `lit.py` | 検査が読む凍結した不変量——作品の4定数、§18 の `Negative`（1行・34本共通）、`Style Motion`、§18 の前書の頭、同一性の塊。⚠️ **`freeze.py` が生成する。手で編集しない。** |
| `freeze.py` | それらを**読んで**取り出す（書き写さない）——手書き3本の仕様・台帳・形式カードから |
| `shared.py` | 同じ理由で `s01`・`s03`・`s05` から取り出した不変の断片 |
| `common.py` | 共通の散文——世界の概念、世界の規則、禁制の床、共通の `must_not` |
| `tpl.py` | **§1–20 の全部**——節の順、§18 の7スロット、雛形自身の文、それらを保つ assert |
| `content/sNN.py` | **1本のショット自身の散文——実際に書かれるもの。**31ファイル |
| `roster.json` | `shots/*.yaml` から取ったショットごとの事実。`roster.py` が組み直す |
| `gen.py` | content モジュール1つを仕様1本へ描く |

**持ち主を分けることが仕掛けである。** 雛形は**ショットを跨いで同一でなければならないもの**を
全部持ち、content モジュールは**そのショット自身のもの**だけを持つ。
雛形の持ち物を content モジュールに書けば、二重に出る。

## 検査の道具

読むだけである。どれも候補を出すだけで、**どれも決めない**。
`verify.py` だけが、毎回の山の後に**通って戻ってこなければならない**。

| ファイル | 問い |
|---|---|
| `verify.py` | 34本すべてが同じ不変量・7スロット・英語のみのスロットを持ち、同一性の塊と「枠に誰も居ない」の間に矛盾が無いか |
| `orphan.py` | 塊を持たないショットが、塊を指す文を持っていないか |
| `absence_probe.py` | 同一性の塊と「人が居ない」の主張を、同じスロットに置いている仕様はどれか |
| `universals.py` | その1本より広い範囲を名乗る文——`every shot`・`all thirty-four`——はどれか |
| `contradiction.py`・`peek.py`・`ten.py` | 同じ検分からの、より狭い探り |

⚠️ **`universals.py` は句でなくクラスに鍵をかける。** 期待した句で鍵をかけた走査は
**言い回しの違うものをすり抜ける**——ひとつの作業の中で3度起きた。
ある1本は動詞が違い、別の1本は探した句そのものを持たず、さらに2本が
同じ偽の全称を別の構文で導入していた。

## ⚠️ 間違えやすい4つ

1. **31本については、`specs/video/*.md` を手で編集するのは生成物を編集することである。**
   次の `gen.py` が上書きする。`content/sNN.py` を直して生成し直す。
   `s01`・`s03`・`s05` は逆で、仕様ファイルが原本である。
2. **`s05` は手書きであり、しかも同一性の塊を持つ。**「手書き3本に塊は無い」は誤りで、
   かつて一度そう信じられた。
3. **`ROOT` は `__file__` から取る。`parents[3]` である。** かつて `parents[2]` と書かれ、
   `<repo>/projects` を指した——そのとき `gen.py` は**31本を `<repo>/projects/projects/` へ書き、
   それでも検算は通った**——**本物の仕様が1バイトも触られていなかったからである。**
   印字された道も正しく見えた（`relative_to(ROOT)` で印字していた）。
   **書き先が在ることは、それが正しい書き先である証拠にならない。**
   `gen.py` と読み手4本は、何かする前に根を assert する。
4. **`roster.json` は導出物であり、古い写しは黙っている。** content モジュールが
   ビート表を宣言しないとき、`gen.py` はここから読む。ショット記録を変えたら `roster.py` で
   組み直す——古い写しは仕様に差分を出さず、**気づかれなかった**。
