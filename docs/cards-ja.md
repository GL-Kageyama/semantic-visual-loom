# カード——Format と Style

**プロンプトは2つの軸から作られ、そのどちらもカードである。** **Format（形式）**は
仕様の形であり、**Style（様式）**はその形の中に描かれる視覚言語である。
**どちらもこのリポジトリの一覧ではない**——**それぞれが Markdown のカードのディレクトリ**であり、
**カードは走る時に、名前で読まれる。**

⚠️ **2つは別々の層であって、1つのものの2つの見方ではない。** 一方の層のカードが
もう一方の層のカードの代わりにはならない——そして**作品は、片方だけを持ちうる。**
`L22` が書かれたのは、その欠陥の後である。

## カードはどこに在るか

**既定では、このリポジトリの隣である**——`distill-essence-engine` の中:

```text
distill-essence-engine/references/formats/   # the format cards
distill-essence-engine/references/styles/    # the style cards
```

⚠️ **そのディレクトリはこのリポジトリの一部ではない**ので、**clone しただけでは手元に無い。**
カードを開けなかった検査は、通ったふりをせず**そう言う**——**「確かめられなかった」は
「確かめた」ではない。**

**こちら側の作品が自前のカードを持つときは、このリポジトリの中に、同じ2層の形で置く:**

```text
references/formats/    # this side's format cards — `video-spec`
references/styles/     # this side's style cards — `sumi-e`
references/grammars/   # the registry — `index.yaml`
references/camera/     # the technique registry — `index.yaml` (100 camera techniques)
```

⚠️ **目録は第三の層ではない。** 自分ではカードを1枚も持たない——**文法である形式カードを
並べるだけである。** そして**走る時に導出せず、ここに置く**のは、
**ショットが使う名に、登録される場所が1つだけ在る**ようにするためである。

⚠️ **2つのディレクトリは、同じものが2つの側から見えているものである**——`_cards_dirs()` は
**層ごとに1つの一覧**を探し、**その一覧の順を決めるのが環境変数である。**

## カードは何枚あるか

**2026-10-29 に数えた。** 数えた範囲は `_cards_dirs()` が探す2つのディレクトリであり、
数え方は**各ディレクトリの `.md` を数え、ミラーを脇に置く**である——`video-spec-ja.md` と
`video-spec-zh.md` は `video-spec.md` の訳であって独立したカードではないので、3つで1枚である。

| ディレクトリ | 形式カード | 様式カード |
|---|---|---|
| `references/`——**このリポジトリ自身のもの** | **16** | **16** |
| `distill-essence-engine/references/`——隣。そこに在る場合 | 45 | 55 |

**16 と 16 の中身。**

- **形式カード 16 枚** = `video-spec` **＋ 15の文法**: `transformation`、`time-fold`、
  `remembered-world`、`impossible-camera`、`meaning-responsive`、`recognizing-world`、
  `coexisting-realities`、そして仮置きの8枚——`recursive-frame`、`scale-rupture`、
  `material-substitution`、`population-emergence`、`temporal-panorama`、`light-as-actor`、
  `frame-escape`、`physics-with-a-rule`。**どれが文法で、どれが別の種類のカードかは、
  「`video-spec` プラス一つの規則」であるかで決まる**——そしてその規則を記録するのが、
  下の目録である。
- **様式カード 16 枚** = `sumi-e` **＋ 画像側から引き継いだ14枚**（`watercolor`、`mokuhanga`、
  `oil-painting`、`gouache-abstract`、`cinematic-still`、`documentary-photo`、`instant-photo`、
  `landscape-photo`、`macro-photo`、`street-photo`、`studio-portrait`、`sketch-broadstroke`、
  `blueprint-plan`、`lab-notebook`）**＋ `impossible-medium`。これがここで唯一、
  画像側の原盤を持たないカードである。**

⚠️ **この 32 枚のうち、ミラーを持つのは1枚だけである。** `video-spec-ja.md` と
`video-spec-zh.md` がその1組であり、**31 枚は訳を持たない英語の正典である**——そして
[`tools/check_i18n.py`](../tools/check_i18n.py) はそれらを自分の文書として数えない。
**あれが数えるのは読み手に渡される文書であり、これらは走る時に開かれるカードである。**

## 文法の目録

`references/grammars/index.yaml` **が文法の一覧であり、検査が読む一覧である。**
文法カードは人へ向けた散文であり、**目録は同じ事実を、検査が開ける形にしたものである。**

```text
- name: transformation            # the name §6 REF_FORMAT uses
  card: transformation            # references/formats/<card>.md
  status: established             # established | provisional
  routes: [WAN 3.0, MINIMAX H3, SEEDANCE 2.5]
  written_into: ["9. ACTION", "11. MOTION"]
  essential_moves: [ … ]          # what the grammar does, in one line each
  negative_conflicts: ["no deforming silhouette"]   # clauses that would forbid the move
  grounding: …                    # the ordinary shot this grammar is measured against
  failure: …                      # the defect it is most often confused with
```

⚠️ **`status` が言うのは「この一覧が正典か」であり、カードが良いかではない。**
`established` の7枚は、このリポジトリが既に持っていたカードである。**`provisional` の8枚は、
作者自身の一覧が差し替える席を埋めている**——ゆえに**仮置きを正典として引かない。**

⚠️ **`routes` は宣言であって、実測ではない。** 実測の理由を持つのは
`coexisting-realities` の1件だけで、そのカード自身が「1本の連続したテイクは二つの場所を
抱えない」と書いている——**ゆえに `WAN 3.0` が除かれるのは、そこだけである。**
**カードが理由を書いていない限り、`routes` を広げも狭めもしない。**

⚠️ **`written_into` は `specmap.SPEC_SECTIONS` の節名（`"9. ACTION"`）で書く**ので、
目録と仕様は1つの綴りを共有する。**カードは同じ一覧を `§9 ACTION` と書く**——
2つの綴り、2人の読者、1つの一覧である。

⚠️ **`negative_conflicts` には、どれかのカードの `## Negative` に既に立っている句だけを
入れる。** **床を増やさない**——作品が §18 へ写したときに**その文法の核を禁じる句**を、
名指しするだけである。**空の一覧は「ここでは禁じていない」であって、
「照合して問題が無い」ではない。**

⚠️ **隣の 45 と 55 も同じ規則で、今日のそのディレクトリのままを数えたものである。**
それらは**画像側の在庫であり、このリポジトリのものではない**——ゆえに
**こちらの何も変わらないうちに、その2つの数は動きうる。**

## カメラの目録

`references/camera/index.yaml` は**カメラ技法の一覧であり、検査が読む一覧である。**
文法の目録とは別の問いに答える——文法の目録は**どの形式カードが文法か**を並べ、
カメラの目録は**動きの名は何か**を並べる。100の技法、それぞれが英語の一行、運動の群、
担える役割、よく組む文法、そして演出上の仕事を運ぶ。

```text
- id: "007"                              # 元の一覧の番号
  name: クレーンアップ
  en: [crane up, camera rises on a crane]  # §18 が土台にする一行
  motion_pattern: [カメラのみ]             # rolemap.MOTION_PATTERNS
  roles: [開示, 情景]                     # 担える仕事——選択ではなく集合
  functions: [転換, 発見]                 # specmap.DRAMATIC_FUNCTION_EN
  grammars: [{card: impossible-camera, confidence: △}]
  travels: true                          # カメラの位置が変わるか
  directing: {job: [解放, 確立], pairs_with: [幕切れで視野を開く, 勝利の後], position: [尾]}
  physical: 位置=上昇しながら弧 ／ …       # カメラの身体が何をするか
  status: draft
```

⚠️ **`roles` が集合であることが設計である。** ひとつの動きは複数の仕事に使える——
**どれなのかはショットの `role` が決める。** 1技法1行に潰した表は**嘘になる。**
⚠️ **`travels` は設計上の事実であって、実測ではない**——パン・チルト・ロール・ズームは
**カメラの立つ位置を変えずに**向きや画角を変えるので、絵が動いても `false` である。

⚠️ **全件が `status: draft`。** 当てはめは一般論の映画作法から起こしたもので、
**どの作品のショットでも測られていない。** **作品の使い方が勝つ**——食い違ったら
**目録を直す。作品を直さない。**

⚠️ **`L53` は一覧を読むが、何も裁かない**: `motion_pattern` は
`rolemap.MOTION_PATTERNS` に、`role` は `rolemap.ROLES` に、function は schema の enum に、
文法のカードは文法の目録に引けなければならない。**その動きがそのショットに正しいかは、
この層が問えることではない。**

## 光の目録

`references/lighting/index.yaml` **が光の演出の一覧であり、検査が読む一覧である。**
カメラの目録とは別のことを答える——あちらは**カメラがどう動くか**、こちらは
**誰が光を作っているか**である。100項目が、英語の句・作り手・担える role・寄る function・
よく組む文法カード・演出上の仕事を持つ。

```text
- id: "038"                              # 出典の番号を3桁に正規化したもの
  name: スリット光
  en: [Slit light]                       # §13 を組む句
  kind: 灯                               # 灯 · 自然 · 光学 · 編集——誰が作るか
  roles: [開示, 様式美]                   # 集合であって、決定ではない
  functions: [発見, 様式美]
  grammars: [{card: light-as-actor, confidence: ○}]
  directing: {job: [焦点, 意味], pairs_with: [帯が1本], position: [中]}
  source: "38"                           # 出典が印字したままの番号
  status: draft
```

⚠️ **柱は `kind` であり、運動の型ではない。** カメラの一覧は `MOTION_PATTERNS` にほぼ一対一で
解けるが、**光には運動の型が丸ごと無い**——列が空なのではなく、列が無い。代わりにあるのが
**誰が光を作るか**である: `灯`（現場の照明）・`自然`（太陽・空・水）・`光学`（レンズと絞り）・
`編集`（後処理）。⚠️ **この4つは、原図の4ページではない**——「編集で足す光の効果」と題した
ページの中身は、編集10・光学14・空気の霧を要するもの1である。

⚠️ **`name` は一意でなく、層もそれを求めない。** 原図は 42 と 43 に同じ和名を付けており、
英名は `High contrast` と `Low contrast` である。**写しは出典を残し、`en` と `source` が
両者を区別する。**

⚠️ **`physical` は無い。** カードが持つのは名前と英名だけで、それ以外は無い——
**出典の無い欄は、欠けた欄ではない**——求めたら推測が入る。

⚠️ **`L55` は一覧を読むが、何も裁かない。** **`L56` は §13 `LIGHTING` を目録の `en` の句へ
当てる**——**このリポジトリで §13 を開く最初の層である。**
⚠️ **`L56` は先頭の語を活用しない**: 光の名は名詞であり、活用を許すと `Bloom` が
`the source blooms` に当たる——**ショットが名指していない光である。**

⚠️ **全件が `status: draft` であり、一覧がいちばん頼る文法カード `light-as-actor` は、
文法の目録で `provisional` である。** **それを引いた件数は註に出る**——
草案の一覧から引かれた暫定のカードは、依然として正典ではない。

## 構図の目録

`references/composition/index.yaml` **は構図の一覧であり、検査が読む一覧である。** 三つ目の
問いに答える——カメラの一覧は**カメラがどう動くか**、光の一覧は**誰が光を作るか**、
こちらは**枠をどう切るか**である。100項目、各項目が英句（または `twin`）・族・種類・
担える役割・傾く関数・常に組む文法・演出上の仕事を持つ。

```text
- id: "079"                              # 原図の番号を3桁に正規化したもの
  name: 一つだけの構図
  en: [isolated subject]                 # §18 `Camera Prompt` を組み立てる句
  source: "79"
  family: 関係と強調                      # 基本の配置 · 視点と切り取り · 奥行きと見せ方 · 関係と強調
  kind: 配置                             # 構図 · 画角 · 配置 — その名が何を指すか
  roles: [様式美, 余白]                   # 集合であり、選択ではない
  functions: [余韻, 決断]
  grammars: []
  population_hint: one                   # これを持つのは2件だけである
  directing: {job: [焦点, 尺度], pairs_with: [群衆], position: [中]}
  physical: 被写体を…                    # カード自身の説明の一行（逐語）
  status: draft
```

⚠️ **`kind` がここの柱であり、光の `kind` ではない。** 光の `kind` は**誰が光を作るか**を
言い、こちらは**その名が何を指すか**を言う——`構図`（51）・`画角`（24）・`配置`（25）。
**同じ鍵を、層がそれぞれの語彙で読む。**

⚠️ **29件が `twin` であり、`twin` は `en` を持たない。** カメラの一覧の 026–050 と 064–075 は
**もともと構図の項目である**——重なりは出典の事実であり、欠陥ではない。
**句が住むのは常に1つの目録だけであり**、`L57` が両方向に閉じる——`twin` を持つ項目は
`en` を持たず、`en` を持つ項目は `twin` を持たず、**構図の句がカメラの句でもあれば、
誰も宣言していない第二の住まいである。**

⚠️ **`family` は原図のページ割りである**——25件ずつ4つの族。技法についての判断ではなく、
カードがどこに載っているかである。

⚠️ **`population_hint` を持つのは2件だけである**——`079` 一つだけの構図（`one`）と
`080` 群衆の構図（`many`）。**その名が枠に何人まで置けるかを決めてしまう**ゆえ、`L58` が
ショットの `population` と照合する。⚠️ **`population` を書いていない記録は註であって
違反ではない**——`L51` が同じ空白を同じように扱う。

⚠️ **`physical` はここには在り、光には無い。** 構図のカードは説明の一行を持ち、
光のカードは名前と英名だけで他に何も持たない。**欄は出典に従う。**

⚠️ **`L57` は一覧を読むが、何も裁かない。`L58` は §18 `Camera Prompt` を読む**——
§1–20 に構図の節は無いゆえ、**`L54` と同じスロットを、別の問いで読む**:
`L54` はカメラがどう動くかを問い、`L58` は枠をどう切るかを問う。

⚠️ **全件が `status: draft` であり、役割と関数は一般論の構図論から当てたものである**——
**作品の実測ではない。** **作品の使い方が食い違えば、作品が勝つ。**

## 環境変数

| 層 | 変数 | |
|---|---|---|
| format | `SVL_FORMATS_DIR` | 形式のカードがどこに在るか |
| style | `SVL_STYLES_DIR` | 様式のカードがどこに在るか |
| registry | `SVL_GRAMMARS_DIR` | `index.yaml` がどこに在るか——**重ねる。置き換えない**: このリポジトリ自身の `references/grammars/` も読まれ続ける |
| camera | `SVL_CAMERA_DIR` | 技法の一覧がどこに在るか——**重ねる。置き換えない**: このリポジトリ自身の `references/camera/` も読まれ続ける |
| light | `SVL_LIGHTING_DIR` | 光の一覧がどこに在るか——**重ねる。置き換えない**: このリポジトリ自身の `references/lighting/` も読まれ続ける |
| composition | `SVL_COMPOSITION_DIR` | 構図の一覧がどこに在るか——**重ねる。置き換えない**: このリポジトリ自身の `references/composition/` も読まれ続ける |

⚠️ **層はそれぞれ自分の変数を読む。** 様式のディレクトリを指しても、
**形式の層は動かない**——**逆もまた同じである。** *読まれていない名乗りが、
読まれた名乗りと同じ顔をしてはならない。*

⚠️ **変数は重ねる。置き換えない。** 指した先のディレクトリが**先に**探され、
**このリポジトリの隣の既定のディレクトリが、その後に探される**——ゆえに
**作品が1枚足しても、エンジンのカードは読めなくならない。** *これが効くのは、
作品が名乗るカードは1つの名前であり、置き換えれば他のすべてのカードを失うからである。*

⚠️ **無いディレクトリを指すことは、誤りではない**——**そのディレクトリは飛ばされ、
既定はそのまま効く。** *間違ったポインタが、黙って「カードが無い」になってはならない。*

⚠️ **相対パスは作業ディレクトリを基準に解かれる**ので、このリポジトリの根から走らせる:

```bash
SVL_FORMATS_DIR=references/formats SVL_STYLES_DIR=references/styles \
  python3 engine/ledger/check.py projects/ippitsu
```

⚠️ **張らなければ、このリポジトリの中のカードは読まれない**——そして
**誰も開けないカードを名乗った仕様は、違反を鳴らす。** だから
**動画仕様を持つ作品は、変数を張る必要がある。** さもなければ、
自分の隣に置いてあるカードが、検査器からは見えない。

## 仕様はどうやってカードを名乗るか

**動画仕様の §6 `REFERENCES` が、そこから引くカードを名乗る:**

```text
- `REF_FORMAT`: `video-spec`
- `REF_STYLE`: `luminous-anime`
```

**1行目が、この仕様がどの形式カードの上に建っているかを名指し、2行目が、
どの様式カードで描かれるかを名指しする。** ⚠️ **どちらも仕様の節ではない**——
**名前が住むのは §6 であり、カードは別のファイルである。**

名前は**カード名**でも**パス**でもよい——**どちらも、何かと比べられる前に1つの名前に畳まれる**
（パスの最後の部分を取り、`.md` を落とす）。⚠️ **どちらの語彙が正しいかは、ここでは決めない**——
層が両方を比べられるようにするだけである。

⚠️ **`bible.style` は作品における様式の住みかであり、`REF_FORMAT` にはそれに当たる欄が無い。**
これは意図である——**2つの経路は別の名前を名乗る**からである。動画の経路は動画仕様のカードを
名乗り、画像の経路は画像のカードを名乗る——だから**名前を1つ書く欄は、
どちらかの経路について偽ることになる。**

## カードが宣言するもの

| 節 | format | style | |
|---|---|---|---|
| `## Environment variables` | 必須 | 必須 | カードが埋める穴。**仕様が名乗ったカードの和が、その仕様が持つべき欄である**（相手は作品ごとに決まる） |
| `## Negative` | 必須 | 必須 | このカードが足す除外 |
| `## Motion character` | —— | 任意 | この様式が動くとき、何をするか |

⚠️ **任意なのは `## Motion character` だけである。** 欄を埋め、**かつ**
`Negative Prompt` に加わるカードは、**残る2つをどちらも宣言しなければならない。**

## どの検査が何を読むか

| 検査 | 読むもの | 鳴る条件 |
|---|---|---|
| `L20` | 様式カードの `## Motion character` | 名指しされた様式にその節が無い——**ゆえに `Style Motion` は在るのに、何も運ばない** |
| `L22` | **画像**仕様、両方の層 | どのカードも宣言していない穴。仕様が埋めない穴を抱えたカード。開けないカード、または `## Environment variables` を持たないカード |
| `L31` | §6 で名指しされた様式カード ⇄ `bible.style` | 住みかと仕様が、別の様式を名乗っている |
| `L32` | §6 で名指しされた形式カード | 名指しされたカードが開けない、または `## Negative` を宣言していない |
| `L42` | §6 `REF_FORMAT`・文法の目録・`dramaturgy.set_pieces` | 名指しされた文法が目録に無い。`written_into` が指す節が無いか空である。§18 が `routes` に無い経路を名乗っている。見せ場の `format` が §6 の名と違う |
| `L45` | 目録の `negative_conflicts` と §18 `Negative Prompt` | 仕様が文法を名指し、その仕様自身の `Negative Prompt` がその文法の核を禁じている |
| `L46` | `aim` の `grammar: <name>` 接頭辞と目録 | `aim` が、目録に無い文法を名乗っている |
| `L53` | カメラの目録と、この基盤の語彙 | `motion_pattern`・`role`・関数・文法カード・形が引けない。⚠️ **目録が開けないのは註** |
| `L54` | §18 `Camera Prompt` と目録の `en` の句 | 全編動かないと言いながら、`travels` が真の技法を名乗っている。⚠️ **目録の句を使っていないプロンプトは註** |
| `L55` | 光の目録と、この基盤の語彙 | `kind`・`role`・関数・文法カード・形が引けない。⚠️ **目録が開けないのは註**。⚠️ **`name` の一意は求めない** |
| `L56` | §13 `LIGHTING` と光の目録の `en` の句 | **無い**——**出口はすべて註である**: §13 を持つ仕様が何本か、どの光を名指したか、何も名指さないのが何本か、**そして §13 が名指した光を §18 の `Visual Prompt` が運んでいないショットはどれか** |
| `L57` | 構図の目録・カメラの目録と、この基盤の語彙 | `family`・`kind`・`role`・関数・文法カード・形が引けない。⚠️ **目録が開けないのは註**。加えて2つの門: `twin` を持つ項目が `en` を持つ（逆も）、`twin` の行き先がカメラの目録に無い、**そして `en` の句がカメラの目録にも載っている** |
| `L58` | §18 `Camera Prompt` と構図の目録の `en` の句 | **1つだけ**: `population_hint` を持つ構図を名乗ったショットの記録の `population` が、名と食い違う。⚠️ **ほかはすべて註**——`population` の無い記録も註の1つである |

⚠️ **`L53` と `L54` は、逆向きの隣である**——**`L53` は目録だけを読み、`L54` は作品を
目録へ当てる。** **どちらも、動きがそのショットに正しいかは裁かない。**
⚠️ **`L55` と `L56` は、光についての同じ対である**——違いは読む向きに1つある:
**`L54` は §18 を読み、`L56` は §13 を読む**——そして §13 は、`L56` までのあいだ、
読む者が1人もいなかった。
⚠️ **`L57` と `L58` は、構図についての同じ対である**——形は光の対に倣う:
**`L58` は §18 `Camera Prompt` を読み、`L54` と同じスロットである**——問いだけが違う。
**1つのスロットを2つの層が読むのは意図である**——ショットは動き、かつ切られる。

⚠️ **`L31`・`L32`・`L42`・`L45`・`L46` が隣に在るのは、意図である**——**同じ §6 と
同じ目録を読み、違うのは鍵だけである。** 離せば、片方が直され、ほかが忘れられる。

⚠️ **`L42` と `L46` は、文法を1つも名指さない作品では、作られると静かである。**
`video-spec` の仕様には登録する文法が無く、`grammar:` で始まらない `aim` は自由文であり、
そのまま通す。**何も名指さない作品は、失敗した作品ではない**——
註が「何本を見たか」を書くので、**沈黙が読めるものとして残る。**

⚠️ **`L20` と `L32` は2つではなく3つの結果を報告する**——**カードの置き場が無いのは註であり、
カードが無いのは違反であり、節を欠いたカードも違反である。** *ディレクトリが無いことと
カードが無いことは別の原因であり、どちらも同じ顔で報告すれば、
読む者はどちらを直せばよいか分からなくなる。*

⚠️ **ゆえに、隣のエンジンを持たない clone では、`L20` と `L32` は違反ではなく註を報告する。**
**同じコードが、置かれた環境によって違う符号を出す**——これが
「このリポジトリはカードを持たない」の正直な読みであり、不具合ではない。

## 読まれないもの

**⚠️ この一覧は、穴として読むこと。やることの一覧として読まないこと。**

- **§6 の残りの鍵**（`REF_CHARACTER` / `REF_SOURCE` / `REF_BIBLE`）。**どの検査も読まない**——
  `L31` が読むのは `REF_STYLE`、`L32` が読むのは `REF_FORMAT` であり、それ以外は無い。
- **様式カードの `## Negative`。** `PROMPT_SLOT_SOURCE` は `Negative Prompt` を
  「§16 ＋ **このカードの Negative** ＋ 様式カードの Negative」と定めており、
  **その2つのカードの項のうち、読まれているのは最初の1つだけである**（`L32`）。
- **カードの中身が正しいか。** 見ているのは**節が在るか**と、
  **宣言された穴が仕様の埋める穴と一致するか**である——**カードの語が出力に何をするかは、
  ここからは見えない。**
- **`## Environment variables` と `## Negative` 以外の、カードのすべての節。** 形式カードは
  自分が埋める穴と、自分が足す除外を宣言する——**それ以外に書いてあることは、
  読み手に向けられている。** ⚠️ **`L22` を動画の経路へ広げられないのは、これが理由である**——
  動画仕様は §1–20 を使い、動画の形式カードが宣言する穴を1つも埋めないので、
  **正しい仕様の上で検査が鳴ってしまう。**
- **文法カードの `## Written into` の散文。** 検査が読むのは目録の `written_into` であり、
  カードの一覧ではない——**カードは `§9 ACTION` と書き、目録は `"9. ACTION"` と書き、
  検査器は目録しか開かない。** 2つの一覧を揃えるのは `L42` の覆いの註であり、
  **目録に無いカードがディスクに在れば、そこが名指しする。**
- **目録の `essential_moves`・`grounding`・`failure`。** これらは文法の意味であり、
  **どの検査も仕様と比べない。** `L45` が読むのは `negative_conflicts` だけである——
  **デバイスがカードの言う通りに働いているかは、ここからは読めない。**
- **`dramaturgy.set_pieces[].why`。** `L42` が比べるのは見せ場の `format` と §6 だけで
  あり、**見せ場がその場所に値するかは作者の判断である。**
- **絵コンテ。** ショット記録のどの欄も `specs/board/` を指さないので、
  **どの検査もそれを開かない**（[`docs/usage.md`](usage-ja.md)）。
