# semantic-visual-loom

**AI生成の物語を、フィルムにするところまで運ぶ基盤。**

> **映像は生成されない。編集される。**

生成モデルが作るのは**標本**である。**作品にするのは編集である。**
だからこの基盤が持つのは生成器ではなく、**制作の工程**——分解・設計・固定・生成・選別・編集・検収。
その中心に置く単位が **ショット** であり、状態を運ぶ器が **制作台帳** である。

**音の姉妹**: `semantic-audio-loom`。同じ作りで対にする（`semantic-` ＋ 感覚の語 ＋ `-loom`）。

## 既存のAI映像ツールとの違い

| | よくある形 | この基盤 |
| --- | --- | --- |
| 単位 | 1プロンプト＝1動画 | **1ショット＝1生成**。作品はショットの列である |
| 状態 | プロンプトに毎回書き直す | **制作台帳**が持つ（連続性＋開示） |
| 文字 | 生成器に描かせる | **文字チャンネル**として分離し、合成で焼く |
| 検収 | 目視 | **事前検証**——仕様の段で矛盾を鳴らす |

**いちばん効くのは2行目である。** 30本のショットを別々のプロンプトで作ると、
**8本目で誰が何を知っていたかが分からなくなる。** 台帳がそれを引き受ける。

## 状態

**生成はこの基盤の中では走らない。事前検証は動く。**

```bash
python3 engine/ledger/check.py projects/hitosara         # デモ「一皿ができるまで」
python3 engine/ledger/check.py projects/ukebi/ukebi-v2   # 受け火 V2
python3 engine/ledger/check.py --self-test               # 検査器が鳴るか
```

**⚠️ 検査は事前検証と、戻ってきたものの突き合わせだけである**（`L25`）。
**生成・選別・編集は基盤に無い**——著者が手で回し、基盤は**記録を読む**。
⚠️ **`L25` は `media/` を開かない。** だから**記録と実物の食い違いは鳴らない**——穴である。

⚠️ **違反0件は「正しい」ではない。** `check.py` は最後にそう言う。
**註と、検査されていない範囲を読むこと。**

## 構成

**在るもの**

```text
semantic-visual-loom/
├── schemas/         # データ構造の正典（bible / ledger / shot-record / take / timeline）
├── engine/ledger/   # 制作台帳と事前検証（生成を走らせずに設計の破綻を潰す）
├── references/      # カード。distill から移管した video-spec を含む
└── projects/        # 作品ごとの実体
```

**⚠️ `projects/` には2種類が同居している。**

- **生の仕様書**——受け火・午前二時の §1–20（`video-*/seg-*/wan-full-spec.md`）。**そのまま残してある。**
- **構造化した記録**——`bible.yaml` / `ledger.yaml` / `shots/`。**`ukebi-v2` と `hitosara` の2本である。**

⚠️ **受け火と午前二時には、生成物を置いていない**——**記録と仕様だけである。**
**古い生成物は、作品のクォリティの統一度を下げる。**

⚠️ **ただし `reference/` の参照資産は残してある**（**9枚**。各セグに複製されている）。
**それは生成物ではなく入力である**——そして**「どのセグに、何を添付したか」の唯一の記録である**
（`wan-full-spec.md` は参照を `REF_STYLE` / `REF_SOURCE` としか書かない）。
⚠️ **消せば、添付の記録ごと消える。**

## デモ `projects/hitosara/`

**「一皿ができるまで」**——粉と水と塩と時間から、パンが一皿になるまで。
10ショット。**受け火から完全に独立している。**

**これは、この基盤が何を読むかを全部見せるために置いてある。**
受け火 V2 が通っていない目録を踏む——種別は15のうち8、`mode` は3つとも、
`attached` は全ショット、`text_channel` と `sound` も使う。

⚠️ **全ショットが2つの経路を持つ。** `spec:` は動画の仕様（§1–20 と §18）、
`key_image:` は画像の仕様（§1–20 を持たない）。
**画像はそのショットの見せ場の1枚であり、動画へは添付（参照画像）として渡る**
——**最初のコマではない**（そうすると、そのショットの変化が画面上で起きなくなる）。
**生成は 画像10枚 → 全部見る → 動画10本**の順に回る。

⚠️ **生成器へ投入するのは §18 だけである。** `specs/video/` の §1–17 は**§18 を組み立てる下敷き**、
§19–20 は**我々の側の記録**——**どちらも投入しない。**
画像の仕様（`specs/image/`）は §18 を持たず、**1つの節の中の2段落**が正典である。
詳細は `projects/hitosara/README.md`。

| | |
|---|---|
| `bible.yaml` | 世界・根本律・視覚言語。**様式は `luminous-anime`**（カードが `Motion character` を持つ） |
| `ledger.yaml` | 台帳は**ひとつ**。人物・場所・道具・**開示**（窯が開く位置、パンが割れる位置） |
| `shots/` | 10本。`role` / `mode` / `beats` / `reference_set` / `attached` / `disclosure_state` / `motion` |
| `specs/video/` | 10本。§1–20 を持つ。§18 が `WAN 3.0` を名乗り、7スロットを埋める。**投入するのは §18 だけ** |
| `specs/image/` | 10本。**§1–20 を持たない。** 7欄（`format` と `style` の穴の和）と1枚の文と、その Negative |
| `media/` | 生成物の置き場。⚠️ **基盤はここを読まない**——在ることも、通ったことも報告しない。**標本だけ** |
| `takes/` | 戻ってきたものの記録。**実物と記録は別である**（下記） |
| `renders/` | **編集で出来たもの（作品）。** ⚠️ **標本と作品は場所で分ける**——名前では分けられない |
| `timeline/` | **空である。** ⚠️ **その空は、報告すらされない** |

⚠️ **`media/` と `takes/` は別である。** 置き場と記録——**置いたことは、記録したことではない。**
だから `media/` に在るのにテイクが無い、という状態がありうる。
**その差は `L25` が註で報告する**——⚠️ **数を数える検査ではなく、読む者への報告として。**
**`takes/` が空なら「テイクの記録が1本も無い」と言う。0件は合格ではない。**

⚠️ **`timeline/` の空は、それすら報告されない**——まだ誰も開かないからである。
**報告しない検査は、通った検査と同じに見える。**

## 予定であって、まだ無いもの

```text
├── skills/          # 分解・設計・台帳・ショット・構成・検収
├── engine/handover/ # 引き渡し票（§18 の7スロット・画像プロンプト・音）と往復検査
├── engine/shot/     # ショット記録の生成・検証
├── engine/visual/   # Visual Asset Engine
├── engine/assembly/ # タイムライン・カット・文字合成・レンダ
├── providers/       # 画像・動画・合成の生成器
├── assets/          # 参照資産（キャラシート・ボード）
├── interchange/     # OTIO / EDL / FCPXML
├── docs/            # 深掘り
└── tools/           # 検査（i18n のミラー欠落・リンク切れ）
```

**⚠️ `timeline/` はスキーマだけが在って、記録が1本も無い。**
`timeline.schema.json` は**まだどの層からも当たっていない**——
⚠️ **`SCHEMAS` 定数に名前は在るが、読む者がいない。**

### 多言語化（en / zh）——⚠️ 唯一のミラー対が、既に食い違っている

⚠️ **このリポジトリに在るミラーは1対だけである**——`references/video-spec.md` の `-en` / `-zh`。
**そして、その1対が正典から遅れている。**

| | 正典 | ミラー |
|---|---|---|
| §18 のスロット | **7**（`Style Motion` が7つ目） | **6**（本文に "Six prompts"） |
| `DURATION` | **尺はモデルが決める** | **Wan 3.0 = 30秒**（⚠️ 実測で偽——戻ってきたクリップは 3.018s / 4.040s など） |

⚠️ **3本とも `i18n-version: 1.0.0` と名乗っている**——
**ずれを検出するはずの印が、「同期している」と言っている。**
そして⚠️ **これを鳴らす検査は無い**（`check.py` は `references/` を開かない）。

**順番:**

1. **ミラーを正典に追いつかせる。** 1対だけなので小さい
2. **そのうえで `tools/check_i18n.py` を書く。** ⚠️ **逆にしてはならない**——
   訳が1つも無い状態では、ミラーの欠落を鳴らす検査が**空になる**
3. **`i18n-version` を上げる。** 上げなければ、また同じずれが起きる

⚠️ **ミラーは生成器へ渡る文字列ではない。** だから**このずれは作品を壊さない**——
壊すのは、**英語で読む人の前提である。**
