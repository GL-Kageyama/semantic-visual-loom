# schemas/ — 数据结构的正典

**本仓库所持有的结构，正典在这里。** `projects/<project>/` 下的 `.yaml` 遵循这五张。

## 为什么是 JSON Schema

**因为事前验证要用机器读它。** `engine/ledger/` 的检查器为了「一次都不跑生成就把设计的破绽压掉」，
要读镜头记录并作出判定。只为了给人读而存在的格式，派不上那个用场。

日语的说明放在 `description` 里。**键是英语、说明是日语**——和交给生成器的字符串（`Negative`、提示词、enum 值）
属于英语不变部是同一个理由，键保持英语。

## 五张

| 文件 | 是什么的结构 | 决定度 |
|---|---|---|
| `bible.schema.json` | **作品台账**。作品世界的不变部。每个项目一份 | 低（不变部与可变部的分界线未决定） |
| `ledger.schema.json` | **制作台账**。把连续性与开示**放在一个文件里**持有。每个项目一份 | 中（开示的形已定。属性的类型仍未定） |
| `shot-record.schema.json` | **镜头记录**。一次生成一张。自身完结 | 高（`unit` 与 `role` 已决定） |
| `take.schema.json` | **镜次**。一个标本一张 | 中（从属于验收的层数） |
| `timeline.schema.json` | **时间线**。采用镜次的序列 ＋ 剪辑点 ＋ 文字 ＋ 声音 | **最低**（以哪一个为正未决定） |

## ⚠️ 这个 schema 报不出来的东西

**「一个变化」的检查，在这个层里不会完结。**

把 `unit` 做成 `{ before, after }` 的对，是为了对「`before` 与 `after` 相同」报警。
**但 JSON Schema 无法比较两个属性**——标准的规格里没有那个功能。
实际测过了——`{ before: "same", after: "same" }` 会被放过去。

**逃路也测过，并且已被封住。** `if`/`then` + `const` 是**枚举**，而不是比较
（只能抓住你写下的那部分字面量，而 `before`/`after` 是自由文本，所以封不住）。
`$data` 引用是没有进入标准规格的提案，参照实现把它当作普通的字面量来处理。
（实测在 `HISTORY.md`。）

**因此这个约束由 `engine/ledger/` 的检查器承担。**
**「做成了对」与「能检查这个对」是两回事。** 只做成对，得不到后者。

同样形状的洞在别处也有。**JSON Schema 保证的是「形」，不是「意义」。**

| 想要报警的东西 | 由谁报警 |
|---|---|
| `before` 与 `after` 相同 | **检查器**（写不进 schema） |
| 是否一个环境（`place` 是否为单数、`beats` 里是否出现多个 `place`） | **检查器** |
| 是否一个时刻 | **检查器** |
| 职能与模式的不一致，是判断还是事故 | **检查器**（如果是判断，就留在记录里） |
| 参照图像里的服装，是否与那个镜头的服装一致 | **检查器** |
| `reference_set`（意图）与 `attached`（实际）的不一致 | **检查器** |
| 形是否正确（必需、类型、enum、`duration` 的格式） | **这个 schema** |

**每一条都在一次都不跑生成的情况下被抓到。**

## 决定的出处

| 什么 | 决定 |
|---|---|
| `unit` = `{ before, after }` | 2026-09-13，作者。自然语言里「是否一个变化」机器无法判定 |
| `role:` = 必需 | 2026-09-13，作者。如果为空，那个镜头按什么来裁就没有被决定 |
| `disclosure` = 以镜头 ID 为键的变化点的序列 | 以 `shot:` 为键。`at` × `clip:` 与 Segment ID 的枚举都落选了，因为两者都想用台账那一侧的坐标来写「哪一个镜头」 |
| `at` = §16 的标题的范围名 | 导出规则从标题取（不是从镜头 ID 取）。测了 87 条，失败为零 |
| 附件的「实际」由镜头记录持有 | Ukebi V1 里有 2 个片段，HANA 出场却没有 HANA 的角色表，而规格里连一条附件的声明都没有 |

## 还没有决定的事情

**它们作为 `description` 写进了 schema。** 主要的几条——

- **职能（`role`）的目录。** 12 种里只有 5 种在使用（已实测、登记未决定）
- **是否把运动的层设为必需栏位。** 「所有镜头都有它」这个主张，与是否允许空栏对不上
- **`beats` 的 `density` 用二值是否够**
- **`disclosure_state` 的值的类型**
- **怎么持有 `… yet`（前方参照）。** §16 在揭示的**紧前面**立起 `no name yet`。这不是状态——这是即将发生之事的预告
- **附件的保存期间**、**是否保留失败的镜次**
- **剪辑的输出格式**（OTIO / EDL / FCPXML / 我们自己的渲染）
